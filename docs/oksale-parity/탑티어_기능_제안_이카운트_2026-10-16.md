**성격**: 제안서. 착수·우선순위·가격 결정은 대표님. 근거는 이카운트 공식 사이트 메뉴명(`ecount.com/kr/ecount/prod/erp`, 2026-10-16 열람)뿐이고, **실제 화면·동작은 분석하지 못했다**(무료체험 로그인이 필요 — 계정 생성은 대표님). 더존·얼마에요는 이번에 조사하지 않았다. 아래 «유니블세일 현황»은 이 저장소 문서(`docs/기능목록_수정안내.md`)에 적힌 것만 근거로 하며, 적히지 않은 것은 «미확인»으로 둔다.

## 2. 제안(우선순위는 «실제 영업 효과 / 위험 제거» 순, 결정은 대표님)
1. **상용 전 필수 — 권한·변경이력·RLS**: 지금은 누구나 앱 키로 읽고 쓰는 구조(미해결 위험). 서버 전용 키+RLS, 사용자·역할(원본의 «관리자 모드 PIN» 확장), 전표 변경·삭제 이력. 이카운트의 «데이터추적»에 대응.
2. **이익관리 보고서**: 품목·거래처별 매출−매입원가 이익. 품목에 매입단가가 이미 있고 전표 하단 정보행에 «이익률»이 있으므로 집계만 더하면 된다. (원본 이익률 산식은 코드 미발견 — 현재 구현은 단가 기반.)
3. **창고별 재고·바코드·모바일(PWA)**: 현장 출고 시 스캔. 창고 구분이 현재 데이터 모델에 있는지 미확인(품목 `StockPosition` 열은 원본에 있음).
4. **은행계좌·카드·국세청 자료 연동**: 이미 보유한 CODEF 연동 경험(별도 프로젝트 유니블CFO)과 같은 계열. 입금 내역 → 수금 자동 대조.
5. **엑셀 업로드(품목·거래처·전표)**: 내보내기는 있고, 가져오기는 미확인.
6. **발주계획**: 안전재고 미달 품목 → 발주서 초안(재고·안전재고 필드는 이미 있음).
7. **매출계획**: 연·월 목표 대비 실적(원본 거래처 «연목표액·월목표액» 칸은 비활성이었음 — 별도 설계).

## 3. 선행 조건 / 막힌 곳
- 이카운트 실화면 분석(REA 표준 흐름의 의사코드·Evidence·Unknowns)에는 **로그인된 체험 계정**이 필요. 대표님이 로그인해 주시면 제가 조작·캡처(CDP 네트워크 포함)한다. 법률 검토(약관·UI 모방 범위)는 법률단.
- Supabase 운영 반영이 먼저다: 현재 `.env.local` 주소가 DNS에서 존재하지 않음(NXDOMAIN, 8.8.8.8로도 확인) → 프로젝트 재생성/재연결 결정이 필요.
- 팝빌 팩스·전자세금계산서 연동은 읽기 호출이 오류 -99010016으로 거부됨(원인 미확인).
