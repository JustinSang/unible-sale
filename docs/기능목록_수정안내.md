# UNIBLE SALE — 기능 목록 · 수정 안내

원본 «머니플러스(OK! 판매재고, OkSale.exe)»와 같은 동작을 목표로 만든 기능들의 **위치·근거·고치는 법**을 한곳에 모았다. 나중에 규칙을 바꾸거나 기능을 고칠 때 여기서 시작한다.
작성: 2026-10-15. 원본 분석 자료 전체는 `docs/oksale-parity/`(이 저장소)와 `~/Desktop/unible_harness/docs/analysis_rea/oksale/`(Ghidra 내보내기 17MB 포함)에 있다.

## 0. 시작하기

| 하고 싶은 일 | 방법 |
|---|---|
| 화면 실행(개발) | `npm run dev` (포트 3000) 또는 아래 «시험 서버»와 함께 3300 |
| 운영 DB 없이 시험 | 터미널 1: `python3 scripts/dev/mock_supabase.py` (127.0.0.1:54321, 쓰기도 흉내) / 터미널 2: `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 NEXT_PUBLIC_SUPABASE_ANON_KEY=mock npx next dev --webpack -p 3300` |
| 타입 검사 | `npx tsc --noEmit -p .` (통과해야 한다) |
| 원본 데이터와 규칙 대조 | `npx tsx scripts/verify_balance_rule.ts` — 기대치: 월 순증감 불일치 16/7,830 · 분기말 17/5,801 · 거래처 원장 8/1,826 · 월별 재고 68/50,373. (오케이세일 `Data/S08~S26.mdb`와 `mdb-export`(mdbtools) 필요) |
| 데스크톱 앱(Windows·Mac) | `cd desktop && npm install && npm run dist` — `desktop/README.md` 참고 |
| DB 스키마 | `scripts/supabase_schema.sql` (멱등 — 여러 번 실행해도 됨) |

**환경 파일 `.env.local`은 저장소에 없다**(키 포함). Supabase·Popbill·Resend 키는 거기에만 둔다.

## 1. 규칙 모음 — «이 규칙은 어디에 있고 무엇이 근거인가»

모든 계산 규칙은 `lib/` 아래 순수 함수로 모아 두었다. 화면은 이 함수를 부르기만 한다 → **규칙을 바꾸려면 lib 한 곳만 고치면 된다.**

| 규칙 | 코드 | 원본 근거 | 비고 |
|---|---|---|---|
| 거래처 월 순증감 = 매출 − 동시수금 − 수금 − 매입 + 동시지급 + 지급 − 매출반품 + 매입반품 (미수 +, 미지급 −) | `lib/ledgerRules.ts monthlyNet` | 원본 `Balance.AC01~12`(S08~S26, 7,830셀 중 16 불일치) · 문서 `월잔액표_Balance_원본규칙_실측.md` | 연도 아닌 «월 번호»로 쌓는 원본 습성(S11.mdb에 두 해 전표) 주의 |
| 분기 집계표(전기잔액·월 매출·수금·잔액, 미수/미지급 분리) | `quarterSummary` | 원본 `QuarterSummaryTable` 열·`Balance >= 0/< 0` | 매출/수금 구분은 추정, 합만 실측 |
| 거래처 원장(품목줄 누적 잔액) | `customerLedger` | `CustomerBookPrintTable` 열 · 품목합=전표합계 실측 | 품목합≠합계 전표는 «(품목합 차액)» 줄 |
| 월별 재고 증감 = −매출수량 + 매입수량 | `monthlyStock` | 원본 `Stock.S01~12`(50,373셀 중 68 불일치), P열·S00은 전 파일 0 | 반품 부호는 표본 3건뿐이라 미확정 |
| 초기이월금(거래처별) | `withOpening`, 설정 `system_config.openingBalances` | 매뉴얼 거래처코드관리 «초기이월금» · `Balance.AC00` | 입력한 거래처만 기준일 이전 거래 제외, 나머지는 전부 반영 |
| 현재 잔액·월별 거래 내역 | `customerBalance`, `customerMonthly` | 매뉴얼 수금지급 캡처(전표년월·매입액·대급금·지급액·매출액·예수금·수금액·잔액) | 대급금=매입세액은 예수금과 대칭(추정) |
| 거래처 단가 이력 Price1→2→3 | `lib/priceHistory.ts shiftPrices` (서버 `app/api/slips/route.ts`) | 원본 `Price.mdb D<거래처ID>` Price1~3 | 날짜 칸은 이관 스키마에 없음 |
| 매입 이력(매입단가·최종매입처1·2) | `lib/purchaseHistory.ts rotatePurchase` | 매뉴얼 상품코드관리 | 밀어 넣는 조건은 추정 |
| 품명의 `{…}` 제외 | `lib/productName.ts` | 매뉴얼 상품코드관리 | 전표 화면·출력에 적용 |
| 중복 이관 전표 제외(대문자 SALES) | `lib/ledgerRules.ts dedupeSlips` | 이관 결함 88건 | **원본 정리 후 삭제할 임시 처리** |
| 부가가치세 포함/별도 | `components/SlipEntryView.tsx` `taxOf`·`vatMode`, 서버 `app/api/slips/route.ts` | 매뉴얼 4쪽 캡처: 포함=세액 10% 가산, 별도=세액 없음 · 실전표 100% 세액 0 | 거래처 `vatType`이 전표 기본값을 정한다 |
| 단가 결정 순서 | `SlipEntryView.tsx getProductPrice` | 매뉴얼: 거래처 이전 단가 우선 → 판매단가, 0이면 첫 거래 · 매입·반출은 매입단가 | |

## 3. 데이터 보정 스크립트(되돌릴 수 있게 만들었다)

| 스크립트 | 하는 일 | 안전장치 |
|---|---|---|
| `scripts/fix_mojibake.py [--dry]` | 이관 때 CP949→Latin-1로 깨진 한글을 복원(품목명 17,538·세금계산서 거래처명 99.7%·거래처 303 등) | 실행마다 `data/*.json.bak_<날짜시각>` 백업, `--dry`로 건수 확인 |
| `scripts/fill_product_costs.py [--dry]` | 원본 `Master.mdb`에서 비어 있던 매입가 4,458건·다른명칭 56건 채움 | 같은 백업 규칙, 이미 있는 값은 안 건드림 |

되돌리기: `cp data/db.json.bak_<…> data/db.json`. `data/`는 `.gitignore`에 있어 **git에는 올라가지 않는다** — 백업 파일이 유일한 복구 수단이므로 지우지 않는다.

## 4. 운영 DB(Supabase)로 옮길 때

1. Supabase 프로젝트 재개(Egress 한도 리셋 10-16 이후) → 2. SQL Editor에서 `scripts/supabase_schema.sql` 실행(멱등) → 3. `npx tsx scripts/migrate_to_supabase.ts`(보정된 `data/db.json`을 읽는다) → 4. Vercel 환경변수 확인·배포.
앱이 공개 anon 키로 읽고 쓴다(RLS 없음) — **상용 전에 서버 전용 키+RLS 필요**(미해결 위험).

## 5. 알려진 한계 · 확인되지 않은 것 (고칠 때 먼저 볼 곳)

- `지름길:` 주석이 달린 곳(`grep -rn "지름길" app components lib scripts`): `dedupeSlips`(임시), `purchaseHistory`(조건 추정), `priceHistory`(날짜 칸 없음), `ledgerRules`(S05~S07·SA/RE/PU/PA 열 미지원, 반품 부호 미확정).
- **원본에서 확인하지 못한 것**: 일계표 집계식(호출자 추적 실패) · 중량단가 용도(`WeightPrice` 109행) · 어음 상태코드 2~5 의미(문자열 순서로 추정) · 할인금액 자동계산식 · 이익률 산식 · 보고서 한글 캡션·배치(.rpt 미해독).
- **미구현**: 어음번호↔어음 대장 자동 연결, F-키로 화면 이동(헤더에는 표기만), 일계표/보고서 43종 중 화면 없는 것(`docs/oksale-parity/보고서_함수_연결표_1차.md`).
- Windows 설치 파일은 실제 Windows에서 실행해 보지 못했다.

## 6. 변경할 때의 약속

1. 규칙을 바꾸면 `lib/`의 해당 함수와 이 문서의 표 한 줄을 같이 고친다.
2. 원본 대조가 가능한 규칙이면 `scripts/verify_balance_rule.ts`를 돌려 불일치 건수가 늘지 않았는지 본다.
3. 화면을 바꾸면 `scripts/dev/mock_supabase.py`로 실제 조작(입력·저장·재조회)까지 확인한다 — 타입 검사만으로 «됐다»고 하지 않는다.
4. 데이터 파일을 건드리는 스크립트는 항상 백업을 만들고 `--dry`를 먼저 돌린다.
