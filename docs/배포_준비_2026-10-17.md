## 3. 시험하지 못한 것 (정직하게)
1. **웹이 스스로 launchd로 재시작하는 경로**(로그인 설정 화면 저장 시) — 운영을 건드릴 수 있어 같은 호출을 시험용 명령으로 바꿔 확인했다. 첫 실제 사용 때 재시작이 안 되면 `launchctl kickstart -k gui/$(id -u)/com.unible.sale.web` 한 번.
2. **복원 스크립트의 launchctl 중지·시작 경로** — 시험용 폴더에서 파일 교체까지만 확인(`NO_LAUNCHCTL=1`).
3. **전표 수정 저장 실패 시 원상복구** — 복구 «효과»(재고·미수금·수불부 되돌림→다시 입힘)는 `test_slip_restore.ts`로 시험했으나, 실패 자체를 일으켜 `slips` 행을 되살리는 분기는 일으킬 방법이 없어 직접 시험하지 못했다.
4. **실제 용지 인쇄**(거래명세표 추가 출력) — 화면 미리보기까지만.
5. 운영 데이터로 «전표 수정 저장»·«재고 점검 보정 실행»을 해 본 적은 없다(복사본에서만).

## 4. 배포 순서 (대표님 승인 후)
1. **백업**(웹 서버가 아직 옛 빌드라 화면 버튼이 없으므로 터미널): 
   ```bash
   sqlite3 data/live/unible_live.sqlite ".backup 'data/live/backups/unible_$(date +%Y%m%d_%H%M%S)_manual.sqlite'"
   ```
2. **협업보드에 «운영 작업 중» 기록**(운영 서버 재시작은 한 창만).
3. **배포**: `bash scripts/server/deploy.sh` — 새 빌드를 `.next-build`에 만든 뒤(3~5분, 그동안 기존 화면 정상) 폴더 교체·재시작, 응답이 없으면 **이전 빌드로 자동 복귀**. 끊김은 몇 초.
4. **배포 후 확인**(각 1분): ①`localhost:3300` 화면 로드 ②전표 목록 «진행» 열 ③«환경설정 / 동기화»에 «로그인·사용자 설정»·«백업»·«변경 이력» 보임 ④전표 입력 품목 검색 «볼트 3/8» 결과(단어별) ⑤미동 발주내역 «미납(미출하) 대사» 148줄 ⑥재고수불부 «재고 점검·보정» 불일치 810(전표 없음) ⑦저장된 전표 하나를 열어 «수정 저장»이 오류 없이 되는지(내용을 바꾸지 말고 같은 값으로) ⑧거래명세표 인쇄 미리보기가 기존과 같은지(추가 출력 꺼짐).
5. **로그인 켜기**(대표님): 환경설정 탭 «로그인·사용자 설정»에서 관리자·직원 계정 입력 → 저장(웹 자동 재시작) → `/`가 로그인 화면으로 가는지 확인.
6. **푸시**(승인 시): 브랜치만 푸시(`git push origin feature/okSale-parity-20261015`), main 병합은 하지 않는다. Vercel(`unible-sale.vercel.app`)은 «Deployment Paused»라 푸시로 클라우드가 바뀌는지는 미확인 — 클라우드 DB를 다시 켤 때는 `scripts/supabase_schema.sql`(새 표·칸 추가분 반영됨)을 먼저 실행.

## 5. 되돌리기
| 상황 | 방법 |
|---|---|
| 배포 직후 화면 이상(응답 없음) | `deploy.sh`가 자동으로 이전 빌드 복귀. 수동: `launchctl bootout`→`rm -rf .next && mv .next-old .next`→`launchctl bootstrap` |
| 설정을 잘못 바꿈 | 환경설정 탭 «변경 이력·되돌리기»(최근 40개) |
| 자료가 잘못 바뀜 | `bash scripts/server/restore_backup.sh <백업>`(미리보기) → `--yes`. 복원 직전 사본이 자동 저장됨 |
| 재고 보정을 잘못 실행 | 재고수불부에 보정 기록(±수량)이 남으므로 반대 조정 또는 백업 복원 |
| 로그인을 잘못 켬 | 터미널 `bash scripts/server/enable_login.sh --off` |
